# Product-specific inspiration

Read for new interfaces and substantial redesigns. Skip for narrow component additions that must preserve an existing system.

Use [Recent.design](https://recent.design/) as a current inspiration index after understanding the product. Search or browse the closest product category and relevant disciplines:

- Websites for marketing sites, portfolios, ecommerce, editorial, SaaS, and product pages.
- Interface for application shells, dashboards, tools, and workflows.
- Typography, Motion, 3D, Product, or Editorial only when that discipline matters to the brief.
- App Screenshots for mobile-product patterns.

Review at least three relevant references when access permits. Capture only transferable observations: hierarchy, density, navigation model, typographic contrast, content rhythm, interaction model, and how the design reflects its subject. Prefer references from the product's domain over globally popular designs.

Synthesize; do not imitate. Do not copy a reference's layout wholesale, branded assets, copy, palette, distinctive animation, or signature motif. Combine observations with the product's own vocabulary and constraints to create one original visual thesis.

Before choosing components, state internally:

```text
Product signal: what is distinctive about this subject?
Reference lessons: which 2–3 principles are useful?
Rejected defaults: what common treatment would make this generic?
Signature: what one product-derived detail will make it recognizable?
```

Vary the solution across projects by evidence, not randomness. Do not force a different library when the established project system is clearly the best fit; vary composition, typography, content model, and signature through product-specific reasoning.
